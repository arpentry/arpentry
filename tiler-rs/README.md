# arpentry-tiler (Rust)

A from-scratch Rust implementation of the Arpentry tiler (`docs/TILER.md`). It
generates `.arpa` tile archives from GeoParquet sources (Overture Maps, Natural
Earth). The C implementation under `../tiler/` is the reference for behaviour and
test fixtures but is not a dependency.

## Architecture

Tile generation is a sort problem, following Planetiler's two-phase design:

```
GeoParquet (WKB geometry)
  → read & decode features
  → profile: assign layer, class, properties, min/max zoom
  → per zoom: simplify + clip to tiles + quantize to tile-local uint16
  → emit sort records keyed by 64-bit (tile_id | layer | rank)
  → external merge sort            ← spatial locality via Hilbert tile_id
  → group consecutive records by tile_id
  → build FlatBuffer .arpt (dict-encode props, brotli)
  → append to .arpa archive (+ fill empty terrain tiles, + write .arpi)
```

The pipeline runs as staged worker pools connected by bounded channels
(backpressure), the external sort being the only hard barrier — see
`pipeline.rs` once implemented.

## Crate choices

- **flatbuffers + flatc** — bindings generated by `flatc` (checked in under
  `src/fb/`, regenerate-only dependency) and read/written with the `flatbuffers`
  runtime. Byte-compatible with the C (flatcc) and web clients — standard file
  identifier at bytes 4..8 (FORMAT.md §7). *(planus was evaluated first but
  places the identifier at bytes 0..4, which the existing clients can't read.)*
- **parquet + arrow** — GeoParquet read. Geometry is a WKB binary column
  decoded by the hand-rolled `wkb` module, so **geoarrow is not needed**.
  (bbox row-group pruning can be added later as a perf optimization.)
- **geo / geo-types** — geometry + Douglas–Peucker.
- **brotli** — per-tile and `.arpi` compression.
- **crossbeam-channel + rayon** — staged concurrent pipeline.
- **memmap2 + bytemuck** — zero-copy `.arpa` reader.
- Hand-rolled: hilbert, rectangle clip, external merge sort (small + hot).

## Milestones

1. **Foundations** ✅ — `hilbert`, `tileid`, `project`, `layers`, `geom`, the
   `.arpa` `archive` writer/reader, generated `fb` bindings, and the `.arpi`
   `tileset` builder (FlatBuffer + brotli). 25 tests passing.
2. **Sort** ✅ — `ExternalSorter`: in-memory buffer with a byte budget, spill
   sorted runs to temp files, k-way min-heap merge. Dependency-free; in-memory
   fast path touches no files; run files auto-cleaned on drop.
3. **Geometry ops** ✅ — `simplify` (Douglas–Peucker, iterative) and `clip`
   (bbox / Liang–Barsky / Sutherland–Hodgman) with direct per-tile `assign_tiles`.
   On `geo-types`; algorithms hand-rolled.
4. **Input** ✅ — `wkb` (hand-rolled WKB→geo-types decoder) and `geoparquet`
   (`parquet`+`arrow` reader with dotted nested-struct paths; geometry is a WKB
   binary column, so no geoarrow needed). `read_naturalearth`/`read_overture`
   conveniences. Verified against the repo's real sample data via `#[ignore]`d
   tests (`cargo test -- --ignored`).
5. **Pipeline + CLI** ✅ — `.arpt` `tile_build` encoder, `profile`, sort-record
   `record` codec (+ WKB writer), single-threaded `pipeline`, and a hand-rolled
   CLI. **No new deps** (std threads + bounded queue can add concurrency later).
   Validated end-to-end on real Natural Earth data (`cargo test -- --ignored`).
6. **Terrain** — empty-tile fill (parity) first; real DEM→mesh (Martini/RTIN +
   octahedral normals) later. Also pending: pipeline concurrency, and perf
   tuning (clipping the global land multipolygon per zoom is the hot spot).

Dependencies are added to `Cargo.toml` per milestone.

## Build & test

```bash
cd tiler-rs
cargo test                 # unit tests (offline)
cargo test -- --ignored    # also run checks against ../data sample files
```

Generate an archive (layer indices: 0 terrain, 1 land_cover, 2 bathymetry,
3 water, 4 land, 5 transportation, 6 land_use):

```bash
cargo run --release -- \
  --output out.arpa \
  --input 4:../data/naturalearth/land.parquet \
  --input 3:../data/naturalearth/lake.parquet \
  --bbox 5.9,45.8,10.5,47.9 --min-zoom 0 --max-zoom 6
```

## Serving tiles

`arpentry_server` is a Rust port of the C `server/`. It exposes the same HTTP
API to the viewer:

```text
GET /{z}/{x}/{y}.arpt   tile      (application/x-arpt, br)
GET /index.arpi         tileset   (application/x-arpi, br)
GET /style.arps         style     (application/x-arps, br)
GET /models.arpm        models    (application/x-arpm, br)
```

It is a blocking, thread-per-connection HTTP/1.1 server (`tiny_http`) with two
tile sources, chosen by the first argument:

```bash
# Serve an .arpa archive (missing tiles fall back to flat terrain):
cargo run --release --bin arpentry_server -- naturalearth.arpa ../style-naturalearth.json 8090

# Procedurally generate tiles on the fly (any non-.arpa path → noise world):
cargo run --release --bin arpentry_server -- tiles ../style.json 8090
```

Arguments are `<tile_dir|archive.arpa> <style_file> [port] [threads]` (default
port 8090, 8 threads), matching the C server. The `/index.arpi` tileset and the
`/models.arpm` library are built once at startup; `/style.arps` is rebuilt from
the JSON file per request.

`flatc` is only needed to regenerate `src/fb/*_generated.rs` after a schema
change (see `src/fb/README.md`); a normal build uses the checked-in bindings.
